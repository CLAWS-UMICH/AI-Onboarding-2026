\section{Write the training data}

The model is only as good as your sentences. One file,
\texttt{data/train.jsonl}, one JSON object per line, exactly one intent each:

\begin{lstlisting}[language=json]
{"text": "what's my primary oxygen at", "intents": ["get_oxy_pri_storage"]}
{"text": "O2 secondary tank pressure?", "intents": ["get_oxy_sec_pressure"]}
{"text": "uh how hot is it in the suit", "intents": ["get_temperature"]}
{"text": "pull up the map", "intents": ["open_menu_navigation"]}
{"text": "drop a waypoint called Crater Rim", "intents": ["Add_waypoint"]}
{"text": "copy that, heading out", "intents": ["unhandled"]}
{"text": "whats the heart rate", "intents": ["get_heart_rate"], "source": "llm"}
\end{lstlisting}

\textbf{Rules}
\begin{itemize}
  \item \textbf{30+ per intent} (50 ideal), and \textbf{at least 20 per intent handwritten}.
        LLM-written rows are allowed on top, but check every one and tag it
        \texttt{"source": "llm"}. The validator counts both.
  \item Save the file as UTF-8 (VS Code does by default).
  \item Mix questions, commands and clipped phrases (``fan RPM?''). 2 to 20 words.
  \item Vary words: oxygen/O2/ox, battery/charge/power, menu/panel/screen.
  \item Sound like speech: ``uh'', ``please'', lowercase, no punctuation.
  \item Always say which one: primary/secondary, A/B, gas/liquid.
  \item Vary names in the five name intents. No near-duplicates.
\end{itemize}

\lstinputlisting[language=Python, caption={\texttt{validate.py}}]{code/validate.py}

\begin{lstlisting}[language=bash]
python ../../code/validate.py data/train.jsonl   # fix until "0 problems"
\end{lstlisting}

\section{Build the model}

\textbf{Pick an encoder.} Three options, all on Hugging Face. MiniLM is the
default; try another once your data is solid. Click a name for its model page
(\texttt{huggingface.co/<model>}).

\begin{center}
\small
\begin{tabular}{@{}llll@{}}
\toprule
Model & Params & Hidden & Notes \\
\midrule
\href{https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2}{\texttt{sentence-transformers/all-MiniLM-L6-v2}} & 22M & 384 & default, fastest \\
\href{https://huggingface.co/BAAI/bge-small-en-v1.5}{\texttt{BAAI/bge-small-en-v1.5}} & 33M & 384 & often more accurate \\
\href{https://huggingface.co/sentence-transformers/all-mpnet-base-v2}{\texttt{sentence-transformers/all-mpnet-base-v2}} & 110M & 768 & biggest, $\sim$5$\times$ slower \\
\bottomrule
\end{tabular}
\end{center}

Set \texttt{MODEL} before running the baseline and training. Both use it, so the
comparison stays fair. \texttt{predict.py} reads your choice back from
\texttt{runs/metrics.json}. Changed models? Re-run both.

\begin{lstlisting}[language=bash]
export MODEL=BAAI/bge-small-en-v1.5       # macOS / Linux
$env:MODEL="BAAI/bge-small-en-v1.5"       # Windows PowerShell
\end{lstlisting}

\section{Evaluate and predict}

\lstinputlisting[language=Python, caption={\texttt{predict.py}}]{code/predict.py}

\begin{lstlisting}[language=bash]
python ../../code/predict.py "add a waypoint named Olympus Ridge"
{"text": "add a waypoint named Olympus Ridge", "selected_intent": "Add_waypoint",
 "confidence": 0.969, "slot": "Olympus Ridge"}
\end{lstlisting}

Anything under 0.5 confidence comes back as \texttt{unhandled}.

\textbf{Held-out accuracy is not the real test}, because you wrote both halves.
Two real tests:

\begin{enumerate}
  \item Write 10+ new sentences you didn't plan for and see what breaks.
  \item \textbf{Peer test.} Score your model on the next member's data
        (alphabetical, wrapping around: Aaron$\to$Evan$\to$Gloria$\to$Raiana$\to$Sam%
        $\to$Utsav$\to$Vivian$\to$Aaron). They need to have pushed their branch.
\end{enumerate}

\begin{lstlisting}[language=bash]
git fetch origin
python ../../code/predict.py --peer evan
\end{lstlisting}

This reads their file straight from git, so nothing lands in your folder.
Common confusions:
primary vs.\ secondary, scrubber A vs.\ B, coolant gas vs.\ liquid, opening
the nav menu vs.\ rerouting, and the coordinate/target/waypoint intents. Fix confusions with better data, not code.

\textbf{Names:} \texttt{extract\_slot} takes the text after the last trigger
word. It's naive (``mark task soil sample complete'' $\to$ \texttt{soil sample
complete}). Improving it is a bonus: copy \texttt{predict.py} into your own
folder, improve it there, and run your copy.

\section{What to hand in}

\textbf{One big PR.} Commit and push as often as you like
(push early so your peer can test on your data), but open a single PR only
when everything below is done. No partial PRs. Only touch your own folder, so
the seven PRs never conflict.

\begin{itemize}[label=$\square$]
  \item \texttt{data/train.jsonl}: 0 problems in \texttt{validate.py}
  \item \texttt{runs/metrics.json}: fine-tuned model beats \texttt{baseline.txt}
  \item \texttt{runs/label2id.json}, \texttt{baseline.txt}
  \item \texttt{notes.md}: model used, results, 10+ unseen sentences, peer test score, what failed
  \item \textbf{Not} \texttt{runs/model.pt} (\texttt{.gitignore} skips it)
\end{itemize}

The PR is done when every box is checked. Ayush reviews and merges. Stuck for
over an hour? Ask in the channel.
